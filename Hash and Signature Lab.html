Hash and Signature Lab

Twelve small experiments covering SHA-256, mining, merkle trees, elliptic curves, RSA and MimbleWimble, plus side-by-side labs on how Bitcoin and Ethereum hash, address, transact and agree on blocks. Everything is computed live in your browser from scratch, and the SHA-256 is checked against your browser's built-in implementation. The keys and ciphers here are deliberately tiny or simplified, so use them for learning only.

Mining: find a nonce

The block is valid only if its double SHA-256 hash starts with enough zero bits. Each extra zero bit halves the number of valid hashes, so the expected number of tries doubles.

Bitcoin's target currently needs roughly 75 to 80 leading zero bits. This page stops at 20 because a browser tab manages around 100,000 hashes a second, and a single mining machine does hundreds of trillions.

    Elliptic curve keys and ECDSA

    Bitcoin's curve is y² = x³ + 7. Here it's calculated mod a small prime so you can see every point. Your public key is the generator point G added to itself d times. Move d and watch the public key jump around unpredictably; that unpredictability is why the public key doesn't reveal d.

    RSA and PGP-style hybrid encryption

    Pick two primes to build a key pair. Encrypting raises a number to e mod n, and decrypting raises it to d. PGP uses RSA only to lock a random session key, and that session key encrypts the actual message.

    n = p·q
    φ = (p−1)(q−1)
    public e
    private d
    RSA signature

    With n this small, two different messages sometimes reduce to the same hash value mod n. With real key sizes, that never happens in practice.

    PGP-style message

    Eve can't unwrap K without Bob's private key, so she has to guess. With keys this small she can try every one.

    Real PGP uses AES with a 128- or 256-bit session key and RSA keys of 2048 bits or more, and checks the message hasn't been modified. Eve's search here takes milliseconds; at those key sizes it would outlast the universe.

    MimbleWimble: hidden amounts that still add up

    MimbleWimble (used by Grin and Litecoin's MWEB) never writes amounts on chain. Each output is a Pedersen commitment C = r·G + v·H, where v is the amount and r is a secret blinding number. Commitments can be added like numbers, so anyone can check that inputs equal outputs plus the fee without seeing a single amount.

    Change to Alice
    On chainCommitment C = r·G + v·HAmount vBlinding r

    Real MimbleWimble also attaches a range proof (a Bulletproof) to every output to show its amount isn't negative. Without that, someone could create money with a −5 output; this demo leaves range proofs out.

    Cut-through

    Two transactions in one block: Alice pays Bob 25 (tx 1), then Bob pays Carol 24 (tx 2). Bob's output is created and spent in the same block, so MimbleWimble can delete it. The checks still pass, and the chain stays smaller.

    Hashes and trees: Bitcoin vs Ethereum

    Bitcoin hashes with double SHA-256 and commits to a block's transactions with a binary merkle tree (lab 05). Ethereum hashes with Keccak-256 and stores every account in a Merkle Patricia trie, a tree keyed by the hex digits (nibbles) of each key.

    Ethereum adopted Keccak before NIST finished the SHA-3 standard. NIST then changed one padding byte, so Keccak-256 and SHA3-256 give different results for the same input.

    From private key to address

    Bitcoin and Ethereum use the same curve, secp256k1, so one private key gives one public key on both. Each chain then hashes and encodes that public key its own way.

    Private key 1 is a published test vector, so you can compare these addresses with any wallet library. Never make a real wallet from a passphrase like this: "brain wallets" get guessed and emptied within minutes. Real wallets use 256 random bits, usually written as a BIP39 word list.

    Transactions: coins vs accounts

    Bitcoin has no balances, only unspent outputs (UTXOs). A payment destroys whole outputs and creates new ones. Ethereum stores a balance and a nonce for each account. A transaction is a signed instruction to move value from one account to another, and its fee is paid in gas.

    Consensus: proof of work vs proof of stake

    Bitcoin picks the next block producer by hashing (lab 03), so blocks arrive at random intervals averaging 10 minutes. Ethereum picks a validator for every 12-second slot, weighted by staked ETH. Validators vote, and every 32 slots (one epoch) a checkpoint can be finalized.
